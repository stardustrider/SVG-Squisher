# Repository and functionality assessment

Assessed source: `d6836f0b32dfd5100167e6fbfa679e976d1bb07f` on 2026-09-07.

SVG Squisher has a useful foundation for converting icon SVGs into simpler paths: a small native executable, focused modules, single-file and folder entry points, FreeType outlines, and a working side-by-side viewer. Its main obstacle to becoming an excellent asset-pipeline tool is conversion trustworthiness. Ordinary supported-looking inputs can change appearance, disappear, crash, or hang while CI remains green.

The recommended product direction is **predictable SVG-to-path conversion with explicit compatibility guarantees and a visual conversion report**. Establish correctness and clear output contracts before expanding the interface or pursuing broad SVG coverage.

This assessment changes documentation only. Findings below describe the assessed commit, not fixes delivered by this report.

## What was verified

- Clean checkout; 46 tracked files, approximately 4,469 lines of native source/headers and 375 lines in `compare.html`.
- Release and Debug builds completed on macOS arm64 with AppleClang 21 and CMake 4.4.3. The Debug executable enabled AddressSanitizer and UndefinedBehaviorSanitizer. CMake was installed in an isolated temporary Python environment because it was absent from PATH.
- The latest GitHub Build run for the assessed commit succeeded. The workflow builds Linux, Windows and macOS, but only invokes `--help` afterward. Local `ctest -N` reported **Total Tests: 0**. Four ad hoc curve SVGs are tracked under `tmp/`; they are not automated tests. [Build run](https://github.com/Geijoh/SVG-Squisher/actions/runs/29283684865), [workflow](https://github.com/Geijoh/SVG-Squisher/blob/d6836f0b32dfd5100167e6fbfa679e976d1bb07f/.github/workflows/build.yml#L31-L38).
- Exercised 25 deliberately targeted SVG fixtures, two CLI argument/path probes, and the curved-stroke fixture through the sanitizer build. These are diagnostic cases, not a representative success-rate benchmark.
- Inspected generated XML and the rendered comparison page at 1280px and 390px widths. Confirmed filename failures, missing-folder behavior, mobile overflow and unescaped HTML rendering through the browser. Text glyph loss/corruption was also visible in the browser. No automated pixel-difference threshold was measured.
- GitHub currently lists v0.1.2 as the latest release, with Windows, Linux and macOS archives. Existing packaged binaries were not downloaded or tested on clean target machines. [Release](https://github.com/Geijoh/SVG-Squisher/releases/tag/v0.1.2).

Build success proves local buildability, not cross-platform runtime fidelity. The simple rectangle control and a path referenced through `use` converted as expected. ASCII text produced outlines, although font selection must be controlled before asserting visual equivalence.

## Fix before the next release

P1 means a release-blocking reliability or fidelity defect for the advertised workflow. P2 means a significant workflow or correctness issue. Line references are to the assessed commit.

| Priority | Confirmed finding | Evidence and corrective direction |
|---|---|---|
| P1 | Normal curved strokes read past allocated memory. | A single quadratic stroke, `M10 50 Q50 0 90 50`, triggers ASan `heap-buffer-overflow` at `src/svg_stroke.cpp:998`, reached through the normal CLI. Subdivision produces more offset segments than original segments; the join loop indexes the original vector using the expanded index. Repair the segment relationship in open, closed and reverse outline construction. Release returned success on the same fixture, demonstrating why a normal run does not rule this out. |
| P1 | Cyclic references crash; malformed paths hang. | `<use id="loop" href="#loop"/>` terminated the Release process with SIGSEGV. A transformed path with `d="M0 0 X"` exceeded a three-second timeout. Add reference-cycle detection, expansion/depth limits and a parser invariant that each iteration consumes input or exits. See `src/svg_traversal.cpp:119-131` and `src/svg_path.cpp:83-105`. |
| P1 | The documented basename-output command fails on macOS. | Supplying `output.svg` produces `filesystem error: in create_directories: No such file or directory [""]`. `src/svg_output.cpp:210` unconditionally creates an empty parent path. Handle an empty parent; add an actual file-conversion CLI smoke test. |
| P1 | Valid compact path data can disappear. | `M0 0 20 0 20 20Z` with `translate(5 5)` becomes `M5,5M25,5M25,25Z`. Subsequent move coordinates should be line segments. `src/svg_path.cpp:105-117` changes `cmd` but keeps using the old `upper`. The same parsing pattern exists in other geometry/stroke parsers. Consolidate parsing into one normalized segment representation. |
| P1 | Styles and opacity change appearance. | `fill="red" style="fill:blue"` becomes red. `fill-opacity="0.25"` and `stroke-opacity="0.25"` become opaque. Overlapping children of a half-opacity group receive independent half-opacity, changing the overlap. Correct the cascade in `src/svg_style.cpp:118-143`; retain distinct paint alpha and group compositing in the output model (`src/svg_path.cpp:303-311`). |
| P1 | Unsupported rendering semantics are silently discarded. | A clipped rectangle becomes a full rectangle; `display="none"` becomes visible; a `use` referencing a `symbol` emits an empty SVG. All returned success without warnings. See `src/svg_dom.cpp:9-15`, `src/svg_style.cpp:46-64` and `src/svg_traversal.cpp:119-131`. Implement the supported cases and diagnose the rest before writing output. |
| P1 | Text conversion corrupts content. | UTF-8 `é` becomes `Ã©`; `A<tspan>B</tspan>C` is emitted as AC followed by B; stroke-only text emits no paths. The character loop reads bytes (`src/svg_text.cpp:327-329`), direct text is collected before spans (`:247-254`, `src/svg_traversal.cpp:46-98`), and text stroke is disabled (`:79-87`). Preserve document order and whitespace, decode Unicode, and process proper positioned glyph runs. |
| P2 | Strokes do not preserve dash behavior. | A dashed circle becomes a solid ring (`src/svg_traversal.cpp:147-169`). A dashed path under `scale(2)` doubles its coordinates but retains width 2 and dash lengths 2 instead of 4 (`src/svg_path.cpp:297-306`). Keep transforms when they affect live stroke metrics or transform the complete stroke representation. |
| P2 | Cleanup assumptions remove intentional geometry. | An open path inheriting red fill and declaring blue stroke loses its fill (`src/svg_traversal.cpp:182-184`). Separately, `--fill white` deletes a large black rectangle when a small detail exists (`src/svg_postprocess.cpp:65-86`). Recoloring and background-removal heuristics need independent, explicit options; faithful conversion must retain the original fill semantics. |
| P2 | Text positioning applies the first dx twice. | `x="10" dx="5"` produces output byte-identical to `x="20"`, not `x="15"`. Both traversal and text layout apply the first offset (`src/svg_traversal.cpp:38,65`, `src/svg_text.cpp:333`). Apply it once within a defined text-chunk layout contract. |
| P2 | CLI typos are accepted. | `input.svg out/result.svg --nonsense` returns success. `src/main.cpp:50-55` accepts unknown switches as operands and only checks for too few operands. Reject unknown options and excess positional arguments. |

SVG's specification defines both implicit lines after moveto and group compositing behavior; these findings concern preservation of defined semantics. [Path commands](https://www.w3.org/TR/SVG2/paths.html#PathDataMovetoCommands), [rendering model](https://www.w3.org/TR/SVG2/render.html#ObjectAndGroupOpacityProperties).

## Further source-backed risks

These were identified in source but did not receive dedicated end-to-end reproductions in this assessment:

- **Output integrity:** `src/svg_output.cpp:209-215` truncates an existing destination and never checks write/flush completion. Use checked writes to a sibling temporary file and atomic replacement; make in-place behavior intentional.
- **Batch reliability:** `src/svg_squisher.cpp:53-57` processes only immediate children, in directory iteration order, and aborts on the first failure. Add deterministic ordering, per-file results, explicit recursion and continue-on-error options, useful totals and an aggregate failure exit code.
- **Paint and viewport transforms:** baking geometry while copying paint definitions unchanged can move `userSpaceOnUse` gradients relative to their shapes. Nonuniform transforms of rotated elliptical arcs also need correct arc math. Root transforms, nested SVG viewports, physical/percentage units and `preserveAspectRatio` are not comprehensively represented by the pipeline.
- **Capability boundaries:** CSS selectors/specificity, `currentColor`, masks, filters, markers, dash offset, vector effects and paint order need explicit support status. A flat list of paths cannot represent all SVG compositing semantics.
- **Font reproducibility:** `--font` is a fallback that can be superseded by the SVG's font family (`src/svg_text.cpp:397-404`). Font discovery is based on hardcoded paths and filename matching; collection faces always use index 0. Missing fonts/glyphs and substitutions need actionable diagnostics and deterministic font identity in reports.
- **Reusable core:** `SvgSquisher::squish_string` is already a useful API seam, but CMake exposes only the executable. A small core library target would enable direct tests and later integrations without coupling them to CLI parsing. Avoid a wider architectural rewrite before the regression corpus exists.

The highest-value UI addition is a **conversion report with a discrepancy inspector**:

1. Connect each input/output pair to warnings, options, font identity, byte sizes, path/command counts and measured visual difference.
2. Add search, failed/missing/changed filters and sorting by largest discrepancy.
3. Provide synchronized zoom/pan, an overlay or blink mode, and light/dark/checkerboard backgrounds.
4. Show intrinsic dimensions and viewBox, plus actual-size inspection. Independently fitting both images into squares can conceal scale or viewport changes.
5. Generate a manifest or standalone report from the CLI, removing dependence on a server's HTML directory listings. Include a small redistributable example corpus so a clean checkout has a working first-run workflow.

## Roadmap toward an excellent converter

| Order | Work | Acceptance criteria |
|---|---|---|
| 1 | Reliability release | Fix the memory over-read, cycle crash, parser hang and basename output failure. Add CLI/conversion tests and ASan/UBSan CI. Malformed inputs finish within a bound with an actionable error. |
| 2 | Fidelity contract and regression suite | Centralize path parsing; fix the confirmed style, text, symbol, stroke and fill cases. Commit independently authored fixtures with expected semantics. Render input/output with fixed fonts at icon and larger sizes, on multiple backgrounds. Establish tolerances for antialiasing and deliberate transforms; fail unexpected differences. Add idempotence, deterministic-output and finite-coordinate checks. |
| 3 | Explicit conversion policies | Distinguish appearance-preserving conversion, filled-path output, monochrome recoloring and heuristic cleanup. A strict profile rejects unsupported semantics before writing output. A preservation profile may retain groups or unsupported subtrees where its target permits them. Every warning identifies the element/property and chosen action. |
| 4 | Batch workflow and review report | Add JSON diagnostics, per-file status, counts, deterministic ordering, recursion/overwrite controls and safe writes. Generate the comparison manifest/report and implement the inspector above. Make a failed or degraded conversion impossible to mistake for a clean success. |
| 5 | Text coverage and release quality | Add Unicode/shaping, defined font override versus fallback behavior, font/missing-glyph reporting and span/whitespace layout tests. Test extracted release archives by converting fixtures. Include licenses/notices, usage documentation, explicit architecture/minimum-platform naming and version information. |
| 6 | Measured optimization and integrations | Add configurable precision/tolerance with a visual error budget, compact serialization, safe path/definition cleanup, and measurements for bytes, geometry complexity, runtime and memory. Expose an installable core library. Consider a local GUI or WebAssembly frontend after the converter contract and tests are dependable. |

Conversion to paths can legitimately increase file size: this audit's ASCII text fixture grew from 138 to 1,759 bytes, and the quadratic stroke from 167 to 1,119 bytes. Those are tiny diagnostic examples, not corpus benchmarks. Report simplification, renderer compatibility and size separately. Do not promise general compression from path conversion alone.

For benchmarks, compare with **usvg** for normalization and **SVGO** for optimization, then measure SVG Squisher's own output and target-renderer compatibility. usvg already documents resolution of shapes, references, nested SVGs and text; SVGO provides configurable optimization plugins. Use them as baselines and investigate reuse only where it improves the tested output contract. Their existence does not establish the correct dependency choice for this C++ project. [usvg](https://github.com/linebender/resvg/tree/main/crates/usvg), [SVGO plugins](https://svgo.dev/docs/plugins/), [resvg test corpus](https://github.com/linebender/resvg-test-suite).

For broader text support, a UTF-8 decoder alone is insufficient. FreeType recommends higher-level layout for scripts that do not map one character to one glyph; HarfBuzz produces positioned glyph runs. Integrate shaping with SVG text chunks, direction, language and font fallback. [FreeType guidance](https://freetype.org/freetype2/docs/reference/ft2-character_mapping.html), [HarfBuzz](https://harfbuzz.github.io/getting-started.html).

The next milestone should be a reliably tested converter and an honest support matrix. Broader file support, stronger optimization and a polished review interface become much more valuable once successful conversion has a measurable meaning.
